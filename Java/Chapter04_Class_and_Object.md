# Chapter 04. 클래스와 객체

## 📅 2026-05-02 (객체 지향과 자바)

### ✅ 배운 내용

**객체의 본질**

- 정의: 실세계의 모든 존재를 객체로 보며, 각 객체는 자신만의 고유한 상태(특성)와 행동을 가짐.
- 상호작용: 객체들은 서로 고립된 것이 아니라, 상대 객체에게 특정 행동을 요청하거나 정보를 주고받는 방식으로 상호 작용하면서 존재함.

**캡슐화 (Encapsulation)**

- 객체를 캡슐로 싸서 내부를 보호하고 볼 수 없게 하는 것으로 객체의 가장 본질적인 특징임.
- 자바에서의 구현: 클래스(Class)라는 캡슐을 사용함.

**상속 (Inheritance)**

- 개념: 슈퍼 클래스(부모)의 특성을 서브 클래스(자식)가 물려받는 것입니다.
- 슈퍼 클래스의 필드와 메소드를 물려받아 코드를 재사용함으로써, 코드 작성에 드는 시간과 비용을 줄임.

**다형성 (Polymorphism)**

- 개념: 같은 이름의 메소드가 클래스 혹은 객체에 따라 다르게 동작하도록 구현된 것을 말함.
- 같은 이름의 메소드가 클래스에 따라 다르게 동작하는 오버라이딩(Overriding) 등이 있습니다.

**객체 지향 언어의 목적**

- 소프트웨어의 재사용성 및 생산성 향상: 이미 만들어진 코드를 재사용하기 쉽고, 복잡한 시스템을 관리하기 용이하게 함으로써 개발 속도를 높임.
- 유지보수의 용이성: 수정이 필요한 부분만 고칠 수 있어 대규모 프로젝트 관리에 유리합니다.

**절차 지향 프로그래밍과 객체 지향 프로그래밍**

(1) 절차 지향 프로그래밍

- 중점: 실행하고자 하는 절차(순서)와 함수 중심임.
- 특징: 데이터를 처리하는 방법(알고리즘)을 순차적으로 나열하며, 데이터와 함수가 분리되어 있음.
- 단점: 프로그램 규모가 커지면 구조가 복잡해져 유지보수와 수정이 어려움.

(2) 객체 지향 프로그래밍

- 중점: 실세계의 개체를 모델링한 객체 중심임.
- 특징: 데이터(필드)와 그 데이터를 다루는 기능(메소드)을 하나의 객체로 묶어서 관리함.
- 장점: 코드의 재사용성이 높고 유지보수가 쉬우며, 대형 프로젝트에 적합함.

## 📅 2026-05-03 (자바 클래스 만들기)

### ✅ 배운 내용

**클래스와 객체**

- 클래스: 객체를 만들어 내기 위한 설계도 혹은 틀.
- 객체: 클래스 모양 그대로 생성된 실체. 클래스의 인스턴스라고도 부름.  
  (예: 붕어빵 틀은 자바 클래스, 붕어빵은 자바 객체)
- 특징: 하나의 클래스로부터 수많은 객체를 생성할 수 있으며, 모두 동일한 속성을 가지지만 자신만의 고유한 값을 가짐.

**클래스 구성 요소**

- 자바 클래스는 `class` 키워드를 사용하여 선언하며, 멤버는 필드와 메소드로 구성됨.
- 필드: 객체의 상태 값을 저장하는 멤버 변수
- 메소드: 객체의 행동(기능)을 구현하는 함수
- 접근 지정자(public): 선언된 클래스나 멤버를 외부 클래스에서 자유롭게 접근할 수 있도록 허용함.
- 생성자: 클래스의 이름과 동일한 메소드를 생성자라하며, 객체가 생성될 때 자동으로 호출되는 특별한 메소드임.

2. 필드와 메소드

- 필드(Field): 객체의 상태 값을 저장하는 멤버 변수.
- 메소드(Method): 객체의 행동(기능)을 구현하는 함수.

**객체 생성 및 접근**

1. 레퍼런스 변수 선언: 객체를 생성하기 전, 객체를 가리킬 레퍼런스 변수를 먼저 선언함.

```java
Circle pizza; // 레퍼런스 변수 선언 (객체가 생성된 것은 아님)
```

2. new 연산자와 객체 생성: 자바에서는 반드시 new 연산자를 사용하여 객체를 생성함.

```java
pizza = new Circle(); // 객체 생성 및 레퍼런스 대입
```

3. 객체 멤버 접근: 생성된 객체의 필드나 메소드에 접근할 때는 `점(.) 연산자`를 사용함.

- `pizza.radius = 10;` (필드 접근)
- `pizza.getArea();` (메소드 호출)

## 📅 2026-05-05 (생성자)

### ✅ 배운 내용

**생성자의 개념과 목적**

- 개념: 객체가 생성될 때 객체의 초기화를 위해 실행되는 메소드
- 특징:
  1. 이름은 반드시 클래스 이름과 동일해야함.
  2. 여러 개 작성할 수 있음
  3. 생성자는 new를 통해 객체를 생성할 때 한 번만 호출됨.
  4. 리턴 타입을 지정할 수 없음.

- 목적: 객체 생성 시점에 필드를 초기화하거나, 필요한 초기 작업을 수행하기 위함

**기본 생성자**

- 개념: 매개변수와 실행 코드가 없어 아무 일도 하지 않고 단순 리턴하는 생성자
- 기본 생성자가 자동으로 생성되는 경우: 클래스 내에 생성자가 하나도 없는 경우, 컴파일러가 자동으로 생성함
- 자동 생성되지 않는 경우: 클래스에 매개변수가 있는 생성자가 단 하나라도 존재하면, 컴파일러는 기본 생성자를 자동으로 삽입해 주지 않음.

## 📅 2026-05-06 (this 레퍼런스)

### ✅ 배운 내용

**this의 기초 개념**

- 정의: 현재 실행되고 있는 객체 자신에 대한 레퍼런스
- 특징: 컴파일러에 의해 자동 관리되므로, 개발자는 `this` 키워드를 사용하여 현재 객체의 멤버에 접근할 수 있음.

**this의 필요성**

- 이름 충돌 해결: 매개변수의 이름과 클래스 멤버 변수의 이름이 같을 때, 이를 구분하기 위해 사용함.
  - (예: `this.radius = radius;` → 좌측은 멤버 변수, 우측은 매개변수)
- 레퍼런스 리턴: 메소드가 객체 자신의 레퍼런스를 반환해야 할 때 `return this;`와 같은 형태로 사용함.

**this()를 이용한 생성자 호출**

- 정의: 클래스 내에서 한 생성자가 다른 생성자를 호출할 때 사용하는 코드
- this 사용 시 주의할 점:
  1. 반드시 생성자 코드에서만 호출할 수 있음
  2. 반드시 같은 클래스 내 다른 생성자를 호출할 때 사용됨.
  3. 반드시 생성자의 첫 번째 문장이 되어야 함.

**객체 치환과 가비지(Garbage)**

- 객체 치환: `=` 연산자를 사용하여 레퍼런스 변수를 치환하면, 변수가 가리키는 객체의 주소값이 바뀜.
- 가비지(Garbage): 객체 치환이나 레퍼런스 변수가 `null`이 되어, 어떠한 레퍼런스 변수도 가리키지 않게 된 메모리 공간을 의미함.
  - 이 가비지들은 자바 가상 기계에 의해 자동으로 수거됨.

## 📅 2026-05-07 (객체 배열)

### ✅ 배운 내용

**객체 배열의 정의**

- 객체에 대한 레퍼런스를 원소로 갖는 배열  
  기본 타입 데이터뿐 아니라, 객체를 원소로 하는 객체 배열도 만들 수 있음.

**객체 배열 생성의 3단계**

- 1단계: 배열 레퍼런스 변수 선언

```java
Circle [] c;
```

레퍼런스 변수 c만 선언할 뿐, 배열을 생성하는 것은 아님.

- 2단계: 레퍼런스 배열 생성

```java
c = new Circle[5];
```

Circle 객체에 대한 레퍼런스 배열이 생성되며, 변수 c가 이를 가리킴. 실제 객체는 아직 존재하지 않음.

- 3단계: 객체 생성

```java
for(int i = 0; i < c.length; i++)
    c[i] = new Circle(i);
```

반복문을 통해 실제 Circle 객체를 생성하여 배열 각 칸에 대입

**배열의 원소 객체 접근**

- c[i] 레퍼런스를 통해 객체의 필드나 메소드에 접근할 수 있음.

```java
for(int i = 0; i <  c.length i++)
    System.out.print((int)(c[i].getAreaa()) + " ");
```

다음 코드는 배열 c에 들어있는 모든 Circle 객체의 면적을 출력함.

## 📅 2026-05-08 (메소드 활용)

### ✅ 배운 내용

**1. 메소드 형식과 접근 지정자**

- 정의: 클래스의 멤버 함수로서, 객체의 동작을 정의함.
- 접근 지정자는 `public`, `private`, `protected`, `디폴트` 4가지가 있으며, 메소드가 다른 클래스에서 호출될 수 있는지 지정하기 위해 사용됨.

**2. 인자 전달 방식: 값에 의한 호출**

자바에서는 항상 변수에 들어있는 값을 복사해서 전달함.

- 기본 타입 전달:
  - 변수의 '실제 값'이 복사됨.
  - 매개변수 값을 메소드 안에서 변경해도 호출한 쪽의 원본 변수 값은 변하지 않음.

- 객체/배열 전달:
  - 객체 자체가 아니라 '객체의 레퍼런스(주소값)'가 복사됨.
  - 주소값을 공유하기 때문에, 메소드 안에서 배열의 내용을 수정하면 원본 배열도 함께 바뀜.

**3. 메소드 오버로딩**

- 정의: 한 클래스 내에서 이름은 같지만 매개변수의 타입이나 개수가 다른 여러 개의 메소드를 중복 작성할 수 있음.

- 여러 개의 메소드가 오버로딩되려면 다음 두 조건을 모두 만족하여야 함.
  1. 메소드 이름이 동일하여야 한다.
  2. 매개변수의 개수나 타입이 서로 달라야 한다.

- 성공 사례:

```java
class MethodOverloading {
  public int getSum(int i, int j) {
    return i + j;
  }
  public int getSum(int i, int j, int k) {
    return i + j + k;
  }
}
```

메소드 이름이 동일하고 매개변수의 개수가 서로 다르기 때문데, 두 메소드는 한 클래스 내에 공존하는데 아무 문제가 없음.

- 실패 사례:

```java
class MethodOverloading {
  public int getSum(int i, int j) {
    return i + j;
  }
  public int getSum(int i, int j) {
    return (double)(i + j);
  }
}
```

위의 getSum() 메소드와 매개변수의 개수, 타입이 모두 같기 때문에 메소드 오버로딩 실패.

## 📅 2026-05-09 (객체의 소멸과 가비지 컬렉션)

### ✅ 배운 내용

**객체의 소멸**

- 자바에는 객체를 생성하는 new 연산자는 있지만 객체를 소멸시키는 연산자는 없음.
- 자동 관리: 사용되지 않는 객체 공간은 자바 가상 기계(JVM)가 직접 관리하여 가용 메모리에 반환합니다.

**가비지(garbage)**

- 정의: 응용프로그램에서 더 이상 사용되지 않게 된 객체나 배열 메모리를 의미함.
- 해당 객체를 참조하는 레퍼런스가 하나도 없을 때 가비지로 판단함. 프로그램이 그 객체에 더 이상 접근할 수 없기 때문임.

**가비지 컬렉션(garbage collection)**

- 정의: 가용 메모리가 일정 크기 이하로 줄어들면 자동으로 가비지를 회수하여 가용 메모리를 늘림.
- 자바 플랫폼에 의해 준비된 가비지 컬렉션 스레드에 의해 처리됨.
- 가비지의 발생 사례:

```java
a = new Person("이몽룡");
b = new Person("성춘향");
b = a;
```

레퍼런스 b는 a가 가리키던 객체를 가리키게 되고, b가 가리키던 처음 객체는 아무도 참조하지 않게 되어 더 이상 접근할 수 없게 됨.

**가비지 컬렉션 강제 요청**

- 응용프로그램에서 System 또는 Runtime 객체의 gc() 메소드를 호출하면 가비지 컬렉션을 요청할 수 있음.

```java
System.gc(); // 가비지 컬렉션 강제 요청
```

- 특징: 이 코드는 가비지 컬렉터를 즉시 실행시키는 명령이 아니라 '요청'에 불과함. 가비지 컬렉션은 자바 플랫폼이 전적으로 판단하여 적절한 시점에 작동시킴.

## 📅 2026-05-10 (접근 지정자)

### ✅ 배운 내용

**패키지(Package)**

- 개념: 서로 관련 있는 클래스들을 그룹화하여 관리하는 폴더(디렉터리)
- 용도: 클래스 이름의 충돌을 방지하고, 효율적인 분산 관리를 가능하게 함.

**자바의 4가지 접근 지정자**

- 정의: 클래스나 멤버들을 다른 클래스에서 접근해도 되는지의 여부를 선언하는 지시어.
  - private, protected, public, 접근 지정자 생략(디폴트 접근 지정자가 있음)

**클래스 접근 지정**

- public: 패키지 제약 없이 어디서나 사용 가능.
- default: 같은 패키지 내의 클래스들만 사용 가능.

**멤버 접근 지정**

- public 멤버: 패키지를 막론하고 모든 클래스들이 접근 가능.
- private 멤버: 비공개를 지시하는 것으로, 오직 해당 클래스 내부에서만 접근 가능
- protected 멤버: 보호된 공개를 지시하는 것으로, 2가지 유형의 클래스에만 접근을 허용함.  
  첫째, 같은 패키지의 모든 클래스에 접근이 허용됨.  
  둘째, 다른 패키지에 있더라도 자식 클래스의 경우 접근이 허용됨.
- default 멤버: 접근 지정자 생략 시 적용되며, 같은 패키지 내부에서만 허용.
