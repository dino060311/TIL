# 📅 2026-05-16 (상속의 개념, 클래스 상속과 객체)

## ✅ 배운 내용

### 1. 상속(Inheritance)

객체 지향에서 **상속**은 부모 클래스에 만들어진 필드와 메소드를 자식 클래스가 물려받는 개념이다.
상속을 사용하면 코드 중복을 줄이고, 클래스 재사용과 확장이 쉬워진다.

#### 상속의 장점

- 클래스의 간결화 → 중복 코드 감소
- 클래스 관리 용이 → 계층적 구조 구성 가능
- 생산성 향상 → 재사용 및 확장 쉬움

### 2. 클래스 상속과 객체

자바에서는 부모 클래스를 `슈퍼 클래스`(super class), 상속받는 자식 클래스를 `서브 클래스`(sub class)라고 한다.

상속은 `extends` 키워드를 사용하여 선언한다.

#### 예제

```java
public class Person {
    ...
}
public class Student extends Person { // Person을 상속받는 클래스 Student 선언
    ...
}
public class StudentWorker extends Student {
    // Student를 상속받는 클래스 StudentWorker 선언
    ...
}
```

`Student`는 `Person`을 상속받고, `StudentWorker`는 `Student`를 상속받기 때문에 `Person`의 멤버도 함께 상속받는다.

#### 상속과 객체

- 상속 선언
  Point를 상속받는 ColorPoint 클래스의 상속 선언은 다음과 같다.

```java
class ColorPoint extends Point {
    ...
}
```

- 서브 클래스 객체 생성  
  Point 클래스의 객체와 ColorPoint 클래스의 객체를 생성하는 코드이다.

```java
Point p = new Point();
ColorPoint cp = new ColorPoint(); // 서브 클래스 객체 생성
```

- `p` 객체 → `Point` 클래스의 멤버만 가짐
- `cp` 객체 → `Point`와 `ColorPoint` 클래스의 멤버를 모두 가짐

즉, 상속을 통해 서브 클래스 객체는 슈퍼 클래스의 기능과 자신만의 기능을 함께 사용할 수 있다.

#### 서브 클래스 객체 활용

`ColorPointEx` 클래스의 `main()` 메소드에서는 `cp` 객체를 통해 부모 클래스 `Point`의 public 멤버와 `ColorPoint`의 public 멤버를 모두 사용할 수 있다.

단, `x`, `y`, `color` 필드는 `private` 접근 제어자를 사용했기 때문에 외부에서 직접 접근할 수 없다.

#### 서브 클래스에서 슈퍼 클래스 멤버 접근

서브 클래스는 슈퍼 클래스의 `private` 멤버를 제외한 멤버를 접근할 수 있다.

예를 들어 `ColorPoint` 클래스는 `Point`의 `set()` 메소드와 `showPoint()` 메소드를 사용할 수 있다.

### 자바 상속의 특징

- 클래스의 다중 상속을 지원하지 않는다.
- 상속의 횟수에 제한을 두지 않는다.
- 계층 구조의 최상위에 java.lang.Object 클래스가 있다.

# 📅 2026-05-17 (상속과 protected 접근 지정자)

## ✅ 배운 내용

### 1. 슈퍼 클래스에 대한 접근 지정

슈퍼 클래스의 멤버는 접근 지정자(`private`, `default`, `protected`, `public`)에 따라 접근 가능한 범위가 달라진다.

| 슈퍼 클래스 멤버에 접근하는 클래스 종류 | private | default | protected | public |
| :-------------------------------------- | :-----: | :-----: | :-------: | :----: |
| 같은 패키지에 있는 클래스               |   ❌    |   ⭕    |    ⭕     |   ⭕   |
| 다른 패키지에 있는 클래스               |   ❌    |   ❌    |    ❌     |   ⭕   |
| 같은 패키지에 있는 서브 클래스          |   ❌    |   ⭕    |    ⭕     |   ⭕   |
| 다른 패키지에 있는 서브 클래스          |   ❌    |   ❌    |    ⭕     |   ⭕   |

#### 슈퍼 클래스의 private 멤버

슈퍼 클래스의 멤버가 `private`으로 선언되면, 서브 클래스를 포함하여 다른 어떤 클래스에서도 접근할 수 없다.  
private은 오직 **현재 클래스 내부에서만 접근 가능**함을 의미한다.

#### 슈퍼 클래스의 default 멤버

슈퍼 클래스의 멤버가 `default`로 선언되면, **같은 패키지에 있는 클래스들만 접근 가능**하다.  
서브 클래스라도 **다른 패키지에 있다면 접근할 수 없다.**

#### 슈퍼 클래스의 public 멤버

슈퍼 클래스의 멤버가 `public`으로 선언되면, 같은 패키지에 있든 다른 패키지에 있든 모든 클래스에서 접근할 수 있다.

### 2. 슈퍼 클래스의 protected 멤버

슈퍼 클래스의 `protected` 멤버는 다음 두 가지 경우에 접근을 허용한다.

- 같은 패키지에 속한 모든 클래스
- 같은 패키지든 다른 패키지든 상속받는 서브 클래스

즉, `protected`는 `default`보다 접근 범위가 넓으며, **상속 관계를 고려한 접근 지정자**이다.

# 📅 2026-05-18 (상속과 생성자)

## ✅ 배운 내용

### 1. 서브 클래스와 슈퍼 클래스의 생성자 호출 및 실행

서브 클래스 객체가 생성될 때는 **서브 클래스의 생성자만 실행되는 것이 아니라, 슈퍼 클래스의 생성자도 함께 실행된다.**  
서브 클래스 객체 안에는 서브 클래스의 멤버와 슈퍼 클래스의 멤버가 모두 포함되어 있다.  
생성자의 목적은 객체 초기화에 있으므로:

- **슈퍼 클래스 생성자** → 슈퍼 클래스 멤버 초기화 수행
- **서브 클래스 생성자** → 서브 클래스 멤버 초기화 수행

즉, 객체 생성 시 슈퍼 클래스와 서브 클래스가 각각 자신의 멤버를 초기화한다.

생성자 실행 순서는 다음과 같다.

1. 슈퍼 클래스 생성자 실행
2. 서브 클래스 생성자 실행

즉, 슈퍼 클래스의 생성자가 먼저 실행된 후 서브 클래스의 생성자가 실행된다.

### 2. 서브 클래스에서 슈퍼 클래스 생성자 선택

원칙적으로 서브 클래스의 개발자는 서브 클래스 생성자에서 함께 실행될 슈퍼 클래스 생성자를 지정해야 한다.
하지만 개발자가 슈퍼 클래스 생성자를 명시적으로 지정하지 않으면, 컴파일러가 자동으로 슈퍼 클래스의 기본 생성자를 호출한다.

#### 슈퍼 클래스의 기본 생성자가 자동 선택되는 경우

개발자의 명시적인 지시가 없는 경우:

- 서브 클래스 생성자가 기본 생성자인 경우
- 서브 클래스 생성자가 매개변수를 가진 생성자인 경우

모두 슈퍼 클래스의 기본 생성자가 자동으로 선택된다.

이 과정은 자바 컴파일러에 의해 자동으로 수행된다.

### 3. super()를 이용한 슈퍼 클래스 생성자 선택

서브 클래스 생성자에서 `super()`를 사용하면 슈퍼 클래스 생성자를 명시적으로 호출할 수 있다.

```java
super();
```

또는 인자를 전달하여 특정 생성자를 호출할 수도 있다.

```java
super(x, y);
```

#### `super()` 사용 규칙

- `super()`는 슈퍼 클래스 생성자를 호출하는 코드이다.
- 반드시 **생성자의 첫 번째 줄에서만 사용 가능**하다.
- `super()`를 생략하면 컴파일러가 자동으로 기본 생성자를 호출한다.

# 📅 2026-05-19 (업캐스팅과 instanceof 연산자)

## ✅ 배운 내용

캐스팅(casting)이란 **타입 변환(type conversion)** 을 의미한다.  
자바에서 클래스에 대한 캐스팅은 **업캐스팅(upcasting)** 과 **다운캐스팅(downcasting)** 으로 나뉜다.

### 1. 업캐스팅

자바에서 서브 클래스는 슈퍼 클래스의 속성을 상속받기 때문에, 서브 클래스 객체는 슈퍼 클래스의 멤버를 모두 가진다.  
따라서 **서브 클래스 객체를 슈퍼 클래스 타입으로 다룰 수 있는데**, 이를 **업캐스팅(upcasting)** 이라고 한다.  
즉, **서브 클래스 객체에 대한 레퍼런스를 슈퍼 클래스 타입으로 변환하는 것**이다.

```java
Person p;
Student s = new Student();
p = s; // 업캐스팅
```

위 코드에서 `p`는 `Student` 객체를 가리키지만, 타입은 `Person`이므로 `Person` 클래스의 멤버만 접근할 수 있다.

예를 들어 `Student` 클래스에만 존재하는 `grade` 필드는 접근할 수 없다.

```java
p.grade = "A"; // 컴파일 오류
```

즉, 업캐스팅된 레퍼런스는 객체 자체는 유지되지만 접근 가능한 멤버 범위가 슈퍼 클래스 기준으로 제한된다.  
또한 업캐스팅은 명시적인 타입 변환 없이 자동으로 이루어진다.

```java
p = (Person)s; // (Person)을 생락하고, p = s;로 해도 됨
```

### 2. 다운캐스팅

업캐스팅과 반대로 캐스팅하는 것을 다운캐스팅(downcasting)이라고 한다.
다음은 Student 객체를 Person 타입의 레퍼런스로 가리키는 업캐스팅 코드이다.

```java
Person p = new Student("김하늘"); // 업캐스팅
```

위와 같이 업캐스팅된 객체를 다시 `Student` 타입으로 변환할 수 있다.

```java
Student s = (Student)p // 다운캐스팅, (Student)의 타입 변환을 반드시 표시
```

다운캐스팅은 업캐스팅과 달리 `명시적으로 타입 변환`을 지정해야 한다.

### 3. 업캐스팅과 instanceof 연산자

업캐스팅을 한 경우, 레퍼런스가 가리키는 객체의 진짜 클래스 타입을 구분하기 어렵다.  
이때 객체의 실제 타입을 확인하기 위해 **`instanceof` 연산자**를 사용한다.

#### instanceof 연산자 사용

사용 형식:

```java
레퍼런스 instanceof 클래스명
```

`instanceof` 연산자의 결과는 `boolean` 값이며,

- 객체가 해당 클래스 타입이면 → `true`
- 아니면 → `false`

```java
if("java" instanceof String) // true
```

이를 활용하면 다운캐스팅 전에 안전하게 타입을 검사할 수 있다.

# 📅 2026-05-21 (메소드 오버라이딩)

## ✅ 배운 내용

### 1. 메소드 오버라이딩의 개념

메소드 오버라이딩은 슈퍼 클래스와 서브 클래스의 메소드 사이에 발생하는 관계로, 슈퍼 클래스에 선언된 메소드와 같은 이름, 같은 리턴 타입, 같은 매개 변수 리스트를 갖는 메소드를 서브 클래스에서 재작성하는 것이다.  
서브 클래스의 개발자는 슈퍼 클래스의 메소드만으로 원하는 기능을 구현하기 어려울 때, 동일한 이름의 메소드를 서브 클래스에 다시 작성할 수 있다.  
즉, 메소드 오버라이딩은 '슈퍼 클래스 메소드 무시하기 혹은 덮어쓰기'로 표현할 수 있다.  
자바에서는 오버라이딩된 메소드가 항상 실행되도록 보장하는데, 이런 처리를 **동적 바인딩** 이라고 한다.

### 2. 오버라이딩의 목적, 다형성 실현

오버라이딩은 슈퍼 클래스에 선언된 메소드를, **서브 클래스마다 자신만의 방식으로 구현**하기 위한 기능이다.  
이를 통해 **같은 이름의 메소드라도 객체에 따라 서로 다르게 동작**할 수 있으며, 객체 지향 프로그래밍의 핵심 특징 중 하나인 **다형성(Polymorphism)** 을 실현할 수 있다.
즉, **하나의 인터페이스(같은 이름)에 서로 다른 구현을 제공하는 것**이 오버라이딩의 목적이다.

### 3. 메소드 오버라이딩의 제약 사항

#### 1) 동일한 원형(signature)으로 작성해야 함

슈퍼 클래스의 메소드와:

- 동일한 이름
- 동일한 매개변수 타입과 개수
- 동일한 리턴 타입

을 가져야 한다.

#### 2) 접근 범위를 더 좁게 변경할 수 없음

슈퍼 클래스 메소드보다 **더 좁은 접근 범위로 오버라이딩할 수 없다.**

접근 범위:

```text
public > protected > default > private
```

예를 들어 슈퍼 클래스 메소드가 `public`이면 서브 클래스에서 `protected`로 변경할 수 없다.

#### 3) 일부 메소드는 오버라이딩 불가능

다음 메소드는 오버라이딩할 수 없다.

- `static`
- `private`
- `final`

### 4. 동적 바인딩: 오버라이딩된 메소드 호출

동적 바인딩(Dynamic Binding)은 **실행할 메소드를 컴파일 시점이 아니라 실행 시점에 결정하는 것**을 말한다.
자바에서는 동적 바인딩을 통해 오버라이딩된 메소드가 항상 실행되도록 보장한다.
어떤 경우이든 자바에서 오버라이딩된 메소드가 있다면 동적 바인딩을 통해 `오버라이딩된 메소드가 무조건 실행된다.`

### 5. 오버라이딩과 super 키워드

서브 클래스에서 `super` 키워드를 이용하면 `정적 바인딩`을 통해 슈퍼 클래스의 멤버에 접근할 수 있다.

```java
super.메소드명();
super.필드명;
```

super는 자바 컴파일러가 제공하는 `슈퍼 클래스에 대한 레퍼런스`이다.
super를 이용하면 슈퍼 클래스의 필드와 메소드 모두 접근 가능하다.

### 6. 오버로딩(overloading)과 오버라이딩(overriding)

오버라이딩은 **슈퍼 클래스의 메소드를 동일한 형태로 다시 작성하는 것**이고,  
오버로딩은 **이름은 같지만 매개변수가 다른 메소드를 여러 개 작성하는 것**이다.

| 비교 요소 |                        메소드 오버로딩                        |              메소드 오버라이딩              |
| :-------- | :-----------------------------------------------------------: | :-----------------------------------------: |
| 선언      | 같은 클래스 또는 상속 관계에서 동일한 이름의 메소드 중복 작성 | 서브 클래스에서 슈퍼 클래스 메소드를 재작성 |
| 관계      |                동일한 클래스 내 혹은 상속 관계                |                  상속 관계                  |
| 목적      |                 사용 편의성 향상, 다형성 실현                 |        부모 기능 재정의, 다형성 실현        |
| 조건      |         이름 동일, 매개변수 타입 또는 개수 달라야 함          |     이름, 매개변수, 리턴 타입 모두 동일     |
| 바인딩    |                정적 바인딩 (컴파일 시 결정)                 |         동적 바인딩 (실행 시 결정)          |
